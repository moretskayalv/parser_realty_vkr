# parser_realty_vkr

Репозиторий содержит код и результаты подготовки датасета по объектам недвижимости в Москве для выпускной квалификационной работы.

Проект реализует полный пайплайн подготовки данных: от парсинга объявлений до очистки, гео-обогащения, построения географических кластеров, генерации синтетических объектов и проверки качества данных через EDA.

Актуальная версия выходных данных — **v3**.

> Папка `old_files` не используется в основном актуальном пайплайне и оставлена только как архив предыдущих версий.

## 3. Основные этапы проекта

### Этап 1. Парсинг объявлений

На первом этапе собираются объявления по объектам недвижимости.

Скрипт парсинга получает ссылки на объявления, открывает карточки объектов и извлекает основные характеристики квартиры и дома.

Собираемые признаки включают:

- цену объекта;
- общую площадь;
- количество комнат;
- этаж;
- этажность дома;
- адрес;
- координаты;
- ближайшее метро и время до метро;
- площадь кухни;
- тип ремонта;
- материал стен;
- год постройки;
- высоту потолков;
- наличие лифта;
- параметры двора, парковки и детской площадки;
- ссылку на объявление.

Результатом этапа являются сырые данные, которые далее используются для гео-обогащения и очистки.

---

### Этап 2. Базовое гео-обогащение

На этом этапе исходные объявления дополняются географическими признаками.

Добавляются или уточняются:

- адрес объекта;
- ближайшая станция метро;
- расстояние до ближайшего метро;
- примерное время пешком до метро;
- расстояние до центра Москвы;
- расстояние до МКАД.

Эти признаки нужны для дальнейшего анализа влияния локации на стоимость недвижимости.

---

### Этап 3. Корректировка расстояния до МКАД

Расстояние до МКАД пересчитывается более точно с использованием геометрии МКАД из файла:

```text
config/mkad_osm.geojson
```

На этом этапе для каждого объекта определяется расстояние до ближайшей точки МКАД.

---

### Этап 4. Обогащение расстояниями до инфраструктуры

Для каждого объекта рассчитываются расстояния до ключевых объектов городской инфраструктуры.

Используется локальный файл:

```text
config/moscow_poi.csv
```

Добавляемые признаки:

- `distance_to_school_km` — расстояние до ближайшей школы;
- `distance_to_kindergarten_km` — расстояние до ближайшего детского сада;
- `distance_to_clinic_km` — расстояние до ближайшей поликлиники или клиники;
- `distance_to_mall_km` — расстояние до ближайшего торгового центра.

Эти признаки отражают доступность социальной и коммерческой инфраструктуры.

---

### Этап 5. Очистка данных и feature engineering

На этапе очистки датасет приводится к формату, пригодному для анализа и дальнейшего машинного обучения.

Основные операции:

- нормализация названий колонок;
- приведение числовых признаков к корректным типам;
- удаление дубликатов;
- удаление строк с критичными пропусками;
- фильтрация выбросов;
- заполнение части пропусков;
- нормализация категориальных признаков;
- создание дополнительных признаков.

Добавляемые признаки:

- `price_per_m2` — цена за квадратный метр;
- `floor_ratio` — отношение этажа квартиры к этажности дома;
- `house_age` — возраст дома;
- `has_metro_near` — бинарный признак близости метро.

## 4. Географические кластеры

В проекте географические кластеры используются как технический слой для генерации синтетических объектов.

Кластеры нужны для того, чтобы синтетические квартиры создавались внутри локально близких зон Москвы, а не случайно по всему городу.

Это позволяет:

- не смешивать объекты из разных частей Москвы;
- сохранять реалистичность координат;
- сохранять пространственную структуру данных;
- генерировать синтетические объекты рядом с реальными объектами.

Результаты кластеризации используются в дальнейшем при генерации синтетических строк.

Дополнительные визуализации кластеров:

```text
geo_generation_clusters.png
geo_generation_clusters_interactive.html.zip
```

## 5. Генерация синтетических объектов

Синтетические объекты создаются на основе реальных квартир внутри одного географического кластера.

В актуальной версии проекта генерация выполняется не простым копированием строк, а через интерполяцию между реальными объектами.

Общая логика генерации:

- берутся реальные объекты внутри одного геокластера;
- выбираются пары похожих объектов;
- числовые признаки интерполируются;
- координаты создаются между координатами родительских объектов;
- к координатам добавляется небольшой шум;
- координаты ограничиваются границами исходного геокластера;
- категориальные признаки берутся от одного из родительских объектов;
- цена пересчитывается согласованно с площадью и ценой за квадратный метр;
- геозависимые признаки временно очищаются для последующего пересчёта.

Служебные признаки:

- `is_synthetic` — признак синтетического объекта;
- `generation_method` — способ генерации;
- `parent_geo_cluster` — кластер, внутри которого был создан объект.

---

## 6. Повторное гео-обогащение синтетических объектов

После генерации синтетических координат старые географические признаки уже не могут использоваться напрямую.

Поэтому для синтетических объектов заново пересчитываются:

- ближайшая станция метро;
- расстояние до метро;
- примерное время пешком до метро;
- расстояние до центра Москвы;
- расстояние до МКАД;
- расстояния до школ;
- расстояния до детских садов;
- расстояния до клиник;
- расстояния до торговых центров.

Актуальный файл после повторного гео-обогащения:

```text
synthetic_objects_geo_enriched_v3.csv
```

## 8. EDA и проверка качества

Для проверки качества данных используются EDA-ноутбуки.

Актуальный ноутбук для сравнения исходных и синтетических данных:

```text
EDA_original_train_vs_synthetic_v3.ipynb
```

Также в репозитории есть ноутбук:

```text
Augmentation_Validation_EDA-2.ipynb
```

В рамках EDA проверяются:

- распределения признаков до и после генерации;
- различия между реальными и синтетическими объектами;
- распределение объектов по геокластерам;
- реалистичность координат;
- реалистичность цен;
- сохранение структуры исходного датасета;
- отсутствие аугментации тестовой выборки.

## 10. Краткое описание

В проекте реализован полный цикл подготовки данных по недвижимости в Москве.

Сначала объявления были собраны с сайта недвижимости. Затем данные были дополнены географическими признаками: адресом, ближайшим метро, расстоянием до метро, расстоянием до центра Москвы, расстоянием до МКАД и расстояниями до объектов городской инфраструктуры.

После этого датасет был очищен: удалены дубликаты, критичные пропуски и выбросы, числовые признаки приведены к корректным типам, а также добавлены новые признаки, включая цену за квадратный метр, возраст дома и отношение этажа квартиры к этажности дома.

В актуальной версии проекта построены географические кластеры, которые используются для генерации синтетических объектов. Синтетические строки создаются внутри локальных географических зон, что позволяет сохранить пространственную реалистичность данных.

После генерации синтетических координат все геозависимые признаки были пересчитаны заново.

Актуальные итоговые данные находятся в файлах с суффиксом `v3`.

Основной итоговый файл:

```text
train_augmented_geo_enriched_v3.csv
```
